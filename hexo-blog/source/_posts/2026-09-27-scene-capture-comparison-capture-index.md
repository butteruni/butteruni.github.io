统计解释：

1. draw 计数包含深度、阴影、透明、全屏和 UI；不能把它直接当作场景可见物体数。
2. EID 是 API 事件定位标识，不是 draw 的连续编号。事件树 action 数也不是完整 API 调用数。
3. 某纹理出现在描述符集合中，并不证明每个像素都采样了它；特别是 descriptor array 和动态分支。
4. 单帧中的 indirect 数量不能证明或否定整个引擎的 GPU-driven 架构。CPU 剔除、前帧 GPU 剔除和缓存结果不会全部暴露在这一帧的这组数里。
5. 三帧内容和可见范围不同，未采集可比的 GPU 时间，不能据 draw 数给游戏性能排名。

### 终末地的 buffer 数少，但不是数据量少

终末地的 57 个 buffer 合计描述长度为 **601,577,060 bytes**，其中 **34 个是 16 MiB** 的 `ReadWrite|Index|Vertex` buffer。木偶的 10,122 个 buffer 合计为 405,412,512 bytes，蕾米为 93,859,036 bytes。

这直接反映了不同的资源打包粒度：终末地把大量几何/可写数据放入较大的 buffer 中，而另外两帧保留了更多小对象。由此可以推断存在较强的池化/大块分配策略，但仅凭这些对象不能还原 CPU 端 allocator、空闲列表或实际显存 heap。

三个截帧记录的 texture `byteSize` 合计分别为 **1,914,632,757 / 1,881,692,689 / 3,132,252,409 bytes**。它们是描述尺寸的总和，包含当前未绑定、缓存或历史资源；不等于当帧显存驻留、峰值占用或实际带宽。
